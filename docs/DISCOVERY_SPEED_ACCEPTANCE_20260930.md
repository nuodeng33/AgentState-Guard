# 观测路径与检测延迟修正验收

日期：2026-09-30。延续发现／接入修正，不扩展 Agent 控制、恢复功能或工作台布局。主代理负责共享缓存、锁与调度、接口和页面整合、服务升级及验收；两名 `gpt-6-sol` high 子代理分别负责 Windows 采集优化和公共会话元数据读取。

## 已交付

- 会话库候选复用公共读取器，覆盖服务配置、OS 用户默认位置和经进程启动身份复核的白名单环境路径。进程线索最多检查 64 项；接口分别报告核验成功、不可用和超过上限未检查的数量。不读取任意用户私有目录，不保存完整环境变量。
- Kimi 同时支持现有 `.kimi-code` 索引与官方 `.kimi`／`KIMI_SHARE_DIR` 工作目录映射；Codex 包含归档及只有归档的库。本机、Docker、WSL 共用格式解析，环境 helper 只负责受限传输。
- Codex 先有界盘点，再解析请求页；返回候选游标及页覆盖信息。共享最多 32 页的脱敏缓存，同页并发请求合并。每次请求仍复核来源、目录身份及页修订；无变化跳过正文元数据解析和重复入库。SQLite 修订包括 WAL。
- 来源视图与本机会话读取不再等待慢进程扫描及无关远端传输。Windows 每轮共享父进程映射，保留独立的前后启动时间检查。后台观察按 2 秒起始间隔调度，超时扫描结束后至少暂停 250 ms；页面可见且无在途请求时每 2 秒查询。
- 安装及位置盘点保持 30 秒周期，新识别 Agent 实例提前触发。程序位置、进程工作目录、会话库和保护目录仍各自保留身份与证据。
- 修复真实 Kimi 库中辅助子目录导致稳定性检查误判的问题。缺失库保留历史身份，实际替换仍拒绝沿用旧绑定。

外部监管保持只读，不创建提供方目录、不启动应用生成索引、不采集聊天正文。内部接管仍要求显式授权的受管运行及控制适配器；本轮未实现的 create／continue／send／stream／cancel 能力保持不可用。缓存不能代替恢复授权或内容完整性校验。

## 测量及边界

以下均是当前机器的有限样本，不是 p95 或端到端时延保证。

| 项目 | 修正前 | 修正后 |
| --- | --- | --- |
| Windows 进程采集一轮 | 402 PID，5.506 秒 | 398 PID，1.115 秒 |
| 自动出现／退出（真实子进程，仅 GET） | 14.83／13.69 秒 | 6.33／3.09 秒 |
| 宿主会话 API | 一次查询因共享锁等待 4.129 秒 | 已测各库约 0.05–0.15 秒 |
| Docker 会话 API | 未作为可比基线 | 最终重启后样本 0.35–1.10 秒；其中一次 Codex 首次查询为 1.10 秒，其后为 0.39 秒 |
| 一万 rollout 候选、20 条首页 | 未作为可比基线 | 冷读 1.069 秒、解析 20 条；未变化检查 1.043 秒、解析 0 条 |

一万条测试说明分页解析有界、重复解析消除；仍需盘点文件元数据，不能宣称大库查询达到 200 ms。检测到 API 的延迟另含扫描及远端传输，页面还受查询周期影响。45 秒被动真实会话变更测量未获得有效样本，因此未形成“实际提供方写入到页面显示”的 p50／p95 验收，也不能由 API 响应时间替代。

## 数据与升级

使用 SQLite backup 备份运行数据库并验证副本，完整性为 `ok`，schema 保持 17；本轮没有新表或迁移。升级后与备份逐项比较：原有两项 Work、一项 Agent 关联、会话身份、Ledger 证据均无丢失或改写；原有检查点、保护版本和 Work 目录关联集合也一致（该运行库这些集合为空）。保护历史的有数据场景由独立回归覆盖。新增观测只追加必要事实。服务有序停止后从原数据库重启。

## 剩余限制

- 未引入 OS 文件监听、常驻远端监听、全库持久索引或新的消息系统；元数据扫描仍有上限和截止时间。瞬时进程、不可访问的进程、没有可核验线索的自定义库仍可能未被发现，接口必须保留不确定状态。
- 已检查的宿主 Codex 库确有多个文件使用相同会话 ID，缺乏可靠合并依据，仍返回部分／降级状态；不能为了显示正常而静默合并。Kimi 辅助目录误判已修复，二者原因不同。
- CloudCLI 真实默认索引仍缺失，成功读取真实 CloudCLI 会话未验收。未知提供方及权限不足不冒称支持。
- 本轮复用原系统，不增加新的控制能力。原有 3D 构建块大小警告仍在，与观测修正无关。

最终版本已在 `http://127.0.0.1:8787` 有序重启，重新核实实际 Kimi 库正常、自定义 Codex 库仍自动可见，并再次通过数据库完整性与历史身份保留检查。
