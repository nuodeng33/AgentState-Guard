# ASG 发现、身份与会话接入

更新：2026-09-30。本轮提供真实自动发现、程序与会话库身份及最小展示；发送任务、继续会话、流式输出和取消尚未实现。发现、可读与可控分别表达。

## 一条公共链路

环境采集 → `signatures.py` 公共分类 → `DiscoveryCatalog` 程序/实例/会话库 → 本地 API → 共享 `AgentIdentity` / `DiscoveryCatalog` 页面组件。静态规则复用原 Agent 分类器，不建立动态插件框架。

- Windows、本地 Docker、已连接 WSL 的可见进程持续观察。未知程序作为未分类候选，不直接伪称 Agent；已识别及用户登记的程序默认显示。
- 安装盘点覆盖 PATH、Windows App Paths、已识别和已登记入口。读取有限包元数据，不执行被盘点的程序，不全盘搜索。PATH 和输出有上限，接口返回覆盖状态；任意新提供方的格式与控制协议不能无依据推断。
- 后台进程观察按 2 秒起始间隔调度；扫描超过间隔时结束后至少暂停 250 ms，不堆积补跑。安装入口与候选会话库每 30 秒盘点，新识别的 Agent 实例触发提前盘点。页面可见时每 2 秒 GET 最新结果；隐藏或请求在途时暂停，不自动 POST 刷新。端到端延迟另加扫描、传输和页面查询耗时。证据变化立即发布，无变化每 30 秒保留观察证据。
- 安装核验与进程存在分别计时；进程出现/退出不替代安装事实。过期、权限不足、部分观察、关闭观察和断开不解释为有效空结果。
- 程序、进程实例、会话库、保护目录各自有身份。实例沿用环境/PID/启动身份；重启后不继承旧 Work 实例关联。来源与会话不证明修改作者。

## 身份和路径

Docker 统一采用原保护模块的完整容器 ID 派生来源 ID。只在本地 daemon 核验完整 ID 后建立旧 ID 别名；名称不参与合并。来源偏好合并以停用优先，旧回执和 Ledger 不改写。

界面显示“程序名称 · 环境名称 · 稳定实例短标识”；容器另显示短容器 ID。详情折叠显示程序位置、PID、工作目录、观察时间和可复制完整 ID。短标识不依赖排序。

Zcode 只有程序位置、父子关系及固定 Electron 角色同时吻合才折叠辅助进程。其余同名进程保留独立。Node/Python 仅提取有界的脚本入口、包信息或固定角色，不保存完整命令行或环境变量；无法核验脚本入口时，不把解释器关联到某个安装程序。

## 会话读取

统一选择“来源 + 会话库 ID”，提供方解析和环境传输分离。候选位置来自服务 HOME、Windows 当前 OS 用户目录、明确配置变量，以及已识别进程中经启动身份复核的白名单路径变量。后者最多检查 64 个进程，Linux 环境读取上限 64 KiB；不保存完整环境变量，不从程序位置猜账号或库目录。进程路径线索只产生库候选，不证明其中某个会话正由该 PID 执行。无法取得线索的自定义位置仍支持环境内核验登记。

- Codex：覆盖 `sessions` 和 `archived_sessions`，只提取请求页的 JSONL 首行元数据，首行上限 256 KiB；不返回或保存指令字段及聊天正文。`metadata_scope=PAGE` 和候选范围明确说明未检查其他页的元数据；`next_offset` 为候选游标，坏条目不阻断后续页。
- Kimi：兼容 `.kimi-code/session_index.jsonl` 与官方 `.kimi/kimi.json` 工作目录映射，包括 `KIMI_SHARE_DIR` 自定义根目录和历史布局；不导入提供方代码，不创建或迁移其文件。
- Zcode：只读任务索引与会话库的必要列，以明确 ID 对应；缺失一侧返回部分状态。桌面任务状态不解释为 PID 正在执行。
- CloudCLI：只读索引，保留底层提供方与原生会话 ID；没有核验原生库归属时不合并引用。库缺失不启动应用生成索引。
- SQLite 以 `mode=ro` 读取，包含 WAL 中的已提交数据，不使用 immutable。库身份绑定目录实体；替换后旧身份不可继续复用。
- 会话每页最多 50 条，默认 50 条；固定读取截止时间与输出上限。每条会话含库 ID，不同库相同原生 ID 不冲突。标题脱敏后仅经本地接口返回，不写入数据库或 Ledger。
- 库不存在、结构不支持、无权限、有效空库、部分读取与读取成功分别表达。会话记录不自动关联进程、任务或执行权。

会话查询复用最多 32 页的脱敏元数据缓存，同页并发请求共用一次读取；每次后续请求仍检查来源、目录身份和页修订，不用 TTL 隐藏目录替换。修订覆盖文件实体、纳秒时间、大小及 SQLite WAL；不完整或不稳定盘点不返回“未变化”。未变化时跳过元数据解析和重复数据库写入。缓存只优化观察，不提供恢复或执行授权。大库仍需有界遍历文件元数据，尚未采用操作系统事件监听或全库持久索引。

来源视图读取和本机只读会话查询不再等待慢进程扫描或其他环境传输。恢复事务和写入锁保持原流程。Windows 原生进程采集每轮共享父进程映射，两次独立创建时间检查仍用于拒绝 PID 重用；psutil 可选优化接口不可用时回退到普通读取。

## 接口

全部沿用本地会话鉴权，不扩展 Device Link 或 AI 数据面。

| 接口 | 契约 |
| --- | --- |
| `GET /api/v1/agents` | 保留运行实例语义；追加程序引用、路径、来源标签和控制能力 |
| `GET /api/v1/discovery/sources` | 来源、观察/连接状态、修订及安装盘点覆盖 |
| `POST /api/v1/discovery/refresh` | 可选的立即刷新；自动更新无需调用 |
| `POST /api/v1/discovery/sources/{id}/configure` | 观察开关及修订检查 |
| `GET /api/v1/discovery/applications` | `source_id`、`limit`、`offset`；默认识别/登记程序，`include_unclassified=true` 加入候选 |
| `POST /api/v1/discovery/applications` | 来源 + 候选 ID 或绝对入口路径；可选名称 |
| `GET /api/v1/discovery/sources/{id}/session-stores` | 独立的会话库分页 |
| `POST /api/v1/discovery/session-stores` | 来源 + 提供方 + 库路径；核验后返回库 ID |
| `GET /api/v1/discovery/sources/{id}/sessions` | `store_id`、`limit`、`offset`；未指定库仅在唯一可用目标时自动选择 |

WSL 发行版发现不启动停止的发行版；“启动并连接”沿用来源操作及持久操作 ID。断开后不后台唤醒。Docker/WSL 使用固定 helper；缺 Python3、权限或连接时明确不可用，不自动安装或提权。

## 存储与兼容

追加 migration 17，新增程序登记和会话库登记两张表；原会话表增加库身份并保留 ID。旧库来源不明的会话标记 `LEGACY_UNVERIFIED`，不只凭原生会话 ID 合并。migration 15/16 保持不变。

发现/接入维护来源与会话；保护模块保留目录、版本、恢复与 Work 关系，通过薄兼容入口调用公共登记逻辑。保护身份、恢复授权与程序展示路径互不替代。升级前使用 SQLite backup，并在副本验证旧 Work、关联、证据及会话身份保留。

## 当前限制

控制能力 `create/continue/send/stream/cancel` 均为 false，原因 `CONTROL_ADAPTER_NOT_IMPLEMENTED`。下一轮交互复用本轮 ID，并实现独立长期通道、审批、占用、重连和幂等。历史会话可读不等于接管外部窗口的进程。

远程 Docker、没有可核验线索的其他 OS 用户私有配置、无法访问的进程及未知库格式不宣称已覆盖。CloudCLI 已安装但真实默认库缺失，成功读取其真实会话仍未验收。采样期间启动又退出的瞬时进程可能遗漏。外部监管保持只读；内部接管仍须显式授权的受管运行及控制适配器，不由路径发现升级得到。
